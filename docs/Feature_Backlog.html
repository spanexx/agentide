Tier 1 — Control Plane foundations

Build in this strict order — each blocks the next. All four shipped.

  • 1. event-bus — shipped 2026-07-26 (@platform/event-bus, 29 tests, v2 upgrade with prefix wildcards + PlatformEvent.id/publishedAt).
  • 2. capability-registry — shipped 2026-07-26 (@platform/capability-registry, 18 tests, owner-scoped clash detection).
  • 3. session-manager — shipped 2026-07-27 (@platform/session-manager, 67 tests, Active/Suspended/Archived lifecycle).
  • 4. plugin-manager — shipped 2026-07-27 (@platform/plugin-manager, 175 tests, full install/update/reload/disable/enable/uninstall + atomic writes).

Tier 2 — Gateway and entry points

All four shipped. gateway-core owns the kernel; platform-capabilities + permission-tiering ship as their own packages.

  • 5. gateway-core — shipped 2026-07-28 (@platform/gateway-core + @platform/agentide, 242 tests; JWT tenant scoping, file-backed secret 0600, audit tenantId, ERROR_CODES).
  • 6. platform-capabilities — shipped 2026-07-28 (25 caps under real owners with read/write split, 4-call migration).
  • 7. permission-tiering — shipped 2026-07-29 (read/act/destructive tier hierarchy enforced end-to-end across 5 packages, 394 tests).

Tier 2.5 — Gateway execution destubbing

Two real execution paths in gateway-core/src/dispatch.ts were stubs at gateway-core ship time. One is fixed; one is open.

  • 8a. gateway-plugin-dispatch — GRILLED 2026-07-30 (design locked: in-process dynamic-import of plugin's entry module at install time; handler map stored in Plugin Manager; dispatch.ts calls via pluginManager.handleInvocation(name, input, sessionId)). Design record: docs/features/gateway-plugin-dispatch/GRILL-gateway-plugin-dispatch.txt. Architecture doc updated: Capability_System.md now explains where the handler lives per type. Next: IMPL pack.
  • 8b. gateway-sdk-dispatch — SHIPPED 2026-07-30. New package @platform/backend-runtime (server.ts + registry.ts + dispatch.ts + events.ts + verify.ts + types.ts). 439 tests across 41 vitest files. Post-impl sim at packages/agentide/scripts/simulate-gateway-sdk-dispatch.mjs (8/8 PRD-TRD scenarios pass; scenario 3 round-trip = 5ms).

Without 8a and 8b, the kernel works but only for the 25 platform caps — runtime plugin capabilities and remote SDK capabilities are unreachable no matter how many adapters are wired. With 8b done, Tier 3 adapters can drive the real dispatch path end-to-end.

Tier 3 — Getting an application connected

  • 8. sdk-node — shipped 2026-07-29 (reference Backend SDK, Node/TypeScript, 55 tests across 7 vitest files, 8 lifecycle events on the bus).
  • 9. mcp-adapter — NOT STARTED. First way an AI agent reaches the platform. Streamable HTTP on port 7100, JSON-RPC 2.0, tools/list + tools/call mapping. Docs at docs/features/mcp-adapter/ (GRILL + PRD-TRD locked, IMPL written, implementation pending).
  • 10. rest-adapter — NOT STARTED.

CLI and WebSocket adapters slot in here too (items 23 + 24 in original backlog), same dependency — order between the four is mostly a priority call, not a technical blocker.

Parallel opportunity: with 8b done, the MCP adapter is the first adapter that exercises the real dispatch path end-to-end. It can be the highest-value single Tier 3 deliverable.

Tier 4 — Browser-native capability

  • 11. sdk-browser — NOT STARTED.
  • 12. browser-runtime — NOT STARTED. Now unblocked at the gateway side (BI[8b) for SDK-style wiring, but blocks on BI[8a] for in-process runtime plugin handlers.

Tier 5 — Visibility

  • 13. dashboard-core — NOT STARTED.
  • 14. devtools-extension — NOT STARTED.
  • 15. vscode-extension — NOT STARTED.

Tier 6 — Ecosystem growth (gated, not just sequenced)

Items 17–21 (Docker / Git / File / K8s / Database runtimes) all need an ownership-track decision — core-team / community / customer-built — before any pipeline run starts. Item 22 (additional Backend SDKs in other languages) is ready once Tier 3 is proven out.

Tier 1 complete. Unblocks Tier 2.

Tier 2 progress — gateway-core shipped 2026-07-28 as @platform/gateway-core + @platform/agentide (242 tests across 23 vitest files; kernel hardening landed via JWT tenant scoping, file-backed secret 0600, ERROR_CODES usage, audit tenantId; meta-package ships createPlatform() composition + agentide CLI subcommands init/status/tenant/token/capability/plugin + install.sh with docker/npx/binary fallback). platform-capabilities shipped 2026-07-28 as @platform/platform-capabilities (308 tests across 26 vitest files; 25 platform caps under real owners with read/write split; platform.*.read wildcard via 3-line authz.ts fix; 9 new handlers in factory.ts; CLI gains --owner / --tier filters on capability list; 4-call migration handles upgrade from pre-BI[6] cleanly). permission-tiering shipped 2026-07-29 — read/act/destructive tier hierarchy enforced end-to-end across five packages: capability-registry (tier field + validateRecord rules + deriveTier helper), plugin-manager (tierFromConvention verb lookup + TIER_REQUIRED error + buildCapabilityRecords integration), platform-capabilities (explicit tier: on all 25 caps), gateway-core (authz.ts tier-hierarchy checkAuthz + namespace wildcard platform.*.<tier> + tier-aware capability.list filter that hides catalog entries a caller cannot invoke), agentide (CLI tier column + --tier filter using first-class card.tier field). 394 tests across 37 vitest files (was 383; +11 tier-convention unit tests); build/lint/typecheck/check-banned-types clean. Drift review "Minor Drift" — 7 gaps all resolved this session (see docs/drift.md D-14 through D-27). Tier 2 complete. Unblocks Tier 3 (sdk-node, mcp-adapter, rest-adapter, cli-adapter, websocket-adapter), Tier 4 (browser-runtime now gets tier-aware authz), and Tier 5 (dashboard-core can show tier badges).

Tier 3 progress — sdk-node shipped 2026-07-29 as @platform/sdk-node — reference Backend SDK (Node/TypeScript, 55 tests across 7 vitest files; lifecycle.test.ts covers 30s reconnect backoff cap with ±20% jitter; register.test.ts covers async-rejection via 8th event sdk.capability.rejected; events.test.ts exercises all 8 bus events; build/lint/typecheck/check-banned-types clean). Public surface: createSdk(config) → SdkInstance with connect(), register(), invoke(), disconnect(), reset(), state(). 8 lifecycle events on the bus (Connection: sdk.connected, sdk.disconnected; Capability: sdk.capability.registered, sdk.capability.unregistered, sdk.capability.rejected; Invocation: sdk.invoke.started, sdk.invoke.completed, sdk.invoke.failed). Browser sim at docs/features/sdk-node/simulate.html drives the real SDK via ws→globalThis.WebSocket shim + dropper callback so the reconnect path is observable. Drift review "Minor Drift" — 5 gaps all resolved this session (see docs/drift.md D-2 → D-9).
